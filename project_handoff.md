## 6. Synthetic Dataset Details

The Python data generator uses:

- Random seed: `42`
- Start date: January 5, 2026
- Activity period: 90 days
- One synthetic district
- Ten synthetic schools
- One thousand synthetic students
- One hundred synthetic teachers
- Two assessments per student
- One hundred assignments

### Expected approximate row counts

| Table | Expected rows |
|---|---:|
| `districts` | 1 |
| `schools` | 10 |
| `students` | 1,000 |
| `teachers` | 100 |
| `activity_events` | Around 28,800 |
| `assessments` | 2,000 |
| `assignments` | 100 |
| `assignment_results` | Around 10,000 |

Activity and assignment-result counts can vary because the generator uses random probabilities.

### Synthetic data-generation behavior

- Students are distributed evenly, with 100 students per school.
- Six schools are categorized as elementary and four as middle schools.
- Student grade levels range from 3 through 8.
- Teachers are distributed across schools.
- Activity event types include `article_opened`, `article_completed`, `quiz_started`, and `quiz_completed`.
- Activity records include event timestamps, minutes spent, and content IDs.
- Each student has Beginning and Ending assessment records.
- Assessment scores are constrained to the range 0–100.
- Assignment results include completed and incomplete assignments.

### Modeling caveats to address

**1. Assessment skill areas**

The generator randomly selects the skill area for each assessment. A student's Beginning and Ending assessments may therefore represent different skill areas.

For the initial literacy-growth dashboard, compare overall Beginning and Ending scores per student. Do not label the difference as skill-specific growth unless the synthetic data generator is updated to keep skill areas consistent.

**2. Engagement and literacy growth**

Assessment growth is currently generated independently of platform engagement. Do not claim that increased engagement causes or predicts higher literacy growth.

A later enhancement could intentionally model a relationship between engagement and growth, with the synthetic assumptions clearly documented.

**3. Platform activity minutes**

The activity dataset records minutes for multiple event types, including opens, completions, and quiz actions. Summing every event's minutes may double-count time.

Initially, label the measure **Platform Activity Minutes**, not verified reading time. Define any reading-specific metric carefully.

**4. Synthetic dates**

The dataset covers a 90-day period beginning January 5, 2026. Dashboard date filters should reflect the generated period rather than imply a full academic year.

## 7. Python Data Loading

The project uses `load_data.py` to load CSV files into PostgreSQL using `psycopg2`.

If the package is not installed, run this command in PowerShell:

```powershell
py -m pip install psycopg2-binary
```

From the project directory, run:

```powershell

py load_data.py
```

Enter the configured PostgreSQL password when prompted.

The loader:
- Reads the CSV files from the `data` directory.
- Inserts records into the eight PostgreSQL tables.
- Omits `event_id` and `assessment_id` so PostgreSQL generates identity values.
- Checks for existing district data to reduce the risk of duplicate imports.
- Uses a transaction to avoid leaving a partial import if the operation fails.

The user reported that loading ran successfully. Row counts still need to be verified.

**Important:** The loader is designed to stop if district data already exists. Do not rerun it blindly. Check table counts and the loader's duplicate-import guard first.

## 9. Data-Quality Checks

Run the following queries in pgAdmin. Save the final versions in `sql/02_data_quality.sql`.

### Check 1: Student distribution by school

```sql
SELECT
    sc.school_name,
    COUNT(st.student_id) AS student_count
FROM schools sc
LEFT JOIN students st
    ON sc.school_id = st.school_id
GROUP BY sc.school_id, sc.school_name
ORDER BY sc.school_name;
```

Expected: 100 students per school.

### Check 2: Activity events by type

```sql
SELECT
    event_type,
    COUNT(*) AS event_count,
    ROUND(AVG(minutes_spent), 2) AS avg_minutes
FROM activity_events
GROUP BY event_type
ORDER BY event_count DESC;
```

Use this output to understand the activity mix.

### Check 3: Assessment coverage and score ranges

```sql
SELECT
    assessment_type,
    COUNT(*) AS assessment_count,
    ROUND(AVG(score), 2) AS average_score,
    MIN(score) AS lowest_score,
    MAX(score) AS highest_score
FROM assessments
GROUP BY assessment_type
ORDER BY assessment_type;
```

Expected: 1,000 Beginning assessments and 1,000 Ending assessments, with scores between 0 and 100.

### Check 4: Assignment completion rate

```sql
SELECT
    COUNT(*) AS total_assignment_results,
    COUNT(completed_date) AS completed_assignments,
    COUNT(*) - COUNT(completed_date) AS incomplete_assignments,
    ROUND(
        100.0 * COUNT(completed_date) / NULLIF(COUNT(*), 0),
        2
    ) AS completion_rate_pct
FROM assignment_results;
```

This uses a non-null completion date to define completed assignments.

### Check 5: Activity date range

```sql
SELECT
    MIN(event_date) AS first_activity,
    MAX(event_date) AS last_activity,
    COUNT(*) AS total_events
FROM activity_events;
```

The activity dates should fall within the generated 90-day period.

### Check 6: Missing key values

```sql
SELECT
    COUNT(*) FILTER (WHERE student_id IS NULL) AS missing_student_ids,
    COUNT(*) FILTER (WHERE event_date IS NULL) AS missing_event_dates,
    COUNT(*) FILTER (WHERE event_type IS NULL) AS missing_event_types,
    COUNT(*) FILTER (WHERE minutes_spent IS NULL) AS missing_minutes
FROM activity_events;
```

These columns are defined as `NOT NULL`, so the counts should be zero if the schema and import behaved as expected.

### Check 7: Duplicate assessment types per student

```sql
SELECT
    student_id,
    assessment_type,
    COUNT(*) AS record_count
FROM assessments
GROUP BY student_id, assessment_type
HAVING COUNT(*) > 1
ORDER BY student_id, assessment_type;
```

Expected: no rows, given the intended two-assessment-per-student design.

### Check 8: Score validation

```sql
SELECT
    COUNT(*) FILTER (WHERE score < 0 OR score > 100) AS invalid_assessment_scores
FROM assessments;
```

Expected: zero invalid scores.

Record the results and any exceptions in the data-quality SQL file or project README.

- Event volume = count of activity-event records.

Be explicit about metric definitions in the dashboard.

### View 2: Literacy Growth

Suggested SQL file: `sql/04_literacy_growth.sql`

Metrics:
- Beginning assessment score
- Ending assessment score
- Student-level score change
- Average score change by school
- Average score change by grade
- Distribution of score changes

Basic logic:

```sql
SELECT
    student_id,
    MAX(score) FILTER (
        WHERE assessment_type = 'Beginning'
    ) AS beginning_score,
    MAX(score) FILTER (
        WHERE assessment_type = 'Ending'
    ) AS ending_score,
    MAX(score) FILTER (
        WHERE assessment_type = 'Ending'
    )
    -
    MAX(score) FILTER (
        WHERE assessment_type = 'Beginning'
    ) AS score_change
FROM assessments
GROUP BY student_id;
```

Join to `students` and `schools` to support grade- and school-level analysis.

This query assumes one assessment of each type per student. Validate that assumption before relying on the results.

### View 3: School Adoption and Assignment Completion

Suggested SQL file: `sql/05_school_adoption.sql`

Metrics:
- Students per school
- Students with at least one recorded platform event
- Student participation rate
- Assignment completion rate
- Assignment scores
- Activity and assignment trends by school

Define participation rate clearly, for example:

`Students with at least one recorded activity event / enrolled students`

Avoid calling this a license activation rate unless the dataset contains a separate license or account-activation measure.

### View 4: Data Quality

Suggested SQL file: `sql/02_data_quality.sql`

Metrics and checks:

- Duplicate records
- Unexpected date ranges
- Assessment coverage
